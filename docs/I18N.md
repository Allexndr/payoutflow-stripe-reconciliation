# Интернационализация (i18n)

**Назначение:** описать архитектуру мультиязычности PayoutFlow и процесс добавления нового языка.

## Поддерживаемые языки (сейчас)

| Код | Язык | Intl tag |
|-----|------|----------|
| `en` | English (default) | `en-US` |
| `ru` | Русский | `ru-RU` |
| `kk` | Қазақша | `kk-KZ` |

Список и метаданные — `src/i18n/config.ts` (`LOCALES`, `LOCALE_LABELS`, `LOCALE_INTL_TAG`).

## Архитектура

Выбрали **lightweight cookie-based i18n без URL-префикса**. Причины:

- Дашборд за авторизацией — canonical URL для SEO там не нужен.
- Не нужно переносить все роуты под `src/app/[locale]/...` → нулевой риск регрессии ссылок.
- Словари строго типизированы через `typeof en`, новые языки обязаны покрыть все ключи (TS поймает пропуск).
- Легко мигрировать на `next-intl` с URL-префиксами позже, если потребуется SEO-версия маркетинга под языки.

### Разрешение локали

`src/i18n/get-locale.ts` — server-only helper. Приоритет:

1. cookie `pf_locale` (если значение в `LOCALES`).
2. `Accept-Language` — первое совпадение (учитывает qualification `q=`).
3. `DEFAULT_LOCALE` — `en`.

### Использование в серверных компонентах

```tsx
import { getLocale, getMessages } from "@/i18n";

export default async function Page() {
  const t = await getMessages();
  const locale = await getLocale();
  return <h1>{t.dashboard.title}</h1>;
}
```

### Форматирование (деньги/даты/проценты)

`src/lib/format.ts` принимает опциональный `locale` и использует `LOCALE_INTL_TAG`:

```ts
formatMoney(1999, "USD", locale) // "$19.99" / "19,99 $" / "19,99 $"
formatDate(iso, locale)
formatPercent(0.0523, locale)
```

### Переключатель языка

`src/components/language-switcher.tsx` — client component. Пишет cookie через
`POST /api/locale` и вызывает `router.refresh()`. Отрисовывается:

- `variant="pill"` — с иконкой Globe, для `AppHeader`.
- `variant="minimal"` — тонкий select, для landing/login/register.

### API

`POST /api/locale` — body `{ "locale": "en" | "ru" | "kk" }`. Валидация через
`isLocale()`. Ставит cookie `pf_locale` (Lax, 1 год, не httpOnly — чтобы JS
мог читать и не делать круг).

## Добавить новый язык

**Предлагаемая очередь приоритета:**

1. `uk` — украинский (рядом с ru-аудиторией, легко переводится на основе ru-файла).
2. `es` — испанский (крупнейший после EN рынок SaaS).
3. `de`, `fr` — EU (GDPR-зона Stripe/PayPal).
4. `pt-BR` — LatAm.
5. `tr`, `uz`, `ky` — региональные для Центральной Азии.

**Шаги добавления (`fr` как пример):**

1. Добавить в `src/i18n/config.ts`:
   ```ts
   export const LOCALES = ["en", "ru", "kk", "fr"] as const;
   LOCALE_LABELS.fr = { native: "Français", english: "French", flag: "FR" };
   LOCALE_INTL_TAG.fr = "fr-FR";
   ```
2. Создать `src/i18n/dictionaries/fr.ts` по шаблону `ru.ts` / `kk.ts`
   (`const messages: Messages = { ... }`). TypeScript не даст скомпилировать,
   если пропущен хоть один ключ.
3. Зарегистрировать словарь в `src/i18n/index.ts` (`DICTIONARIES`).
4. `npm run build && npm test` — тесты и сборка сами подтвердят совместимость.

## Что локализовано прямо сейчас

- Landing (`/`) — полностью.
- Auth (`/login`, `/register`) — полностью, включая формы.
- Header/nav — полностью.
- 404 (`/not-found`) — полностью.
- Dashboard (`/dashboard`) — заголовки, фильтры, статусы, итоговые карточки.
- Settings (`/settings`) — заголовки, основные лейблы Stripe/Plaid/Billing/CSV.
- Privacy / Terms — заголовки и плашка «canonical in English» (юридический
  текст намеренно оставлен на английском как канон).

## Что ещё не переведено (fallback — EN)

- Детальная страница выплаты `/dashboard/payouts/[payoutId]` — внутренние
  компоненты (manual match panel, activity feed) ещё на EN. Все ключи
  уже присутствуют в словаре (`payoutDetail.*`) — осталось прокинуть в
  компоненты.
- Текст юридических документов (Privacy/Terms) — осознанно EN-only.
- Server-side валидационные строки API (Zod errors) — возвращаются на EN
  и маппятся на локализованное сообщение на фронте (см.
  `login-form.tsx` → `invalidMessage`).

## Нюансы

- Cookie `pf_locale` выставлен `SameSite=Lax`, срок жизни 1 год.
- `<html lang>` проставляется из `getLocale()` в `src/app/layout.tsx` —
  важно для a11y-скринридеров и для выбора варианта шрифта Geist.
- Geist уже подгружает `latin` + `cyrillic` сабсеты — русский и казахский
  отображаются без лишних запросов.
